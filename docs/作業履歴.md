### 2. リングのサイズを調整可能に

### 3. 完了までの口数を可変に

6口固定だったものを **2〜12口** で変更できるようにした。

- 設定パネルにスライダー `#goal`（現在値を数字で表示）
- `buildBoard()` で弁当箱のマスと燃料ゲージを口数ぶん組み直す。
  おかずの絵文字は6種なので `OKAZU[i % 6]` で循環させる
- 7口以上は2段組にする（列数 = `Math.ceil(goal/2)`）
- **1マスが巨大化する問題の修正**: `1fr` 列と `aspect-ratio:1/1` の組み合わせでは、
  列が少ないと1マスが219pxまで肥大した（口数2で弁当箱の高さが237px）。
  列数から弁当箱の横はばを決める（`min(92vw, 列数×76px)`）ようにして、
  どの口数でも1マス63〜68pxに収まるようにした
- 弁当箱の高さが口数で変わるため、CSS変数 `--deck` を実測値から更新するようにした。
  「たべた！」ボタン・ロケット・設定パネルの縦位置がこれに追従する
- 炎の伸び幅も口数に応じて調整（`38/goal` px ずつ）してはみ出さないようにした
- ドラッグ中は数字だけ動かし、指を離した時点（`change`）で組み直す
- 途中で口数を減らして到達済みになった場合は、そのままお祝いへ進む

## 2026-08-18 発射後の処理落ちの原因調査と修正、エフェクト実装ルールの明文化

対象ファイル: `index.html`、`CLAUDE.md`（新規）

### 症状

ロケット発射後に処理が重くなる。

### 原因（計測で特定）

推測せず、実際の粒の構成を再現してベンチマークを取った。

| 条件（375×812・デスクトップ実測） | 1フレーム |
|---|---|
| 修正前・発射直後 1244個 | 38.45ms（26fps） |
| スプライト化のみ | 9.86ms |
| 個数削減のみ 340個 | 13.39ms |
| 両方 | 3.19ms |

種類ごとに切り分けると **絵文字400個で28.0ms**、**火花800個で17.6ms**。
原因は「1粒ごとに毎フレーム、重いCanvas APIを呼んでいた」ことで、具体的には
`ctx.font` への代入と `fillText`（フォント解決＋絵文字カラーグリフのラスタライズ）、
および `createRadialGradient` の毎粒毎フレーム生成。
デスクトップでこの数字なので、実機のスマホは3〜5倍かかる。

粒の量そのものも過剰だった。発射時の内訳は
噴射 35ms間隔×16個×1.9秒 ≒ 864個、煙44個、星のバースト 12回×34個 = 408個で、
上限1200個に張り付いていた。

### 修正

**描画方式（効果が大きい方）**

- 絵柄を起動時に一度だけ 64×64 のキャンバスへ焼く（スプライト化）。
  火花は色相6種、煙1種、絵文字は使うぶんだけ。毎フレームは `drawImage` のみ
- 種類ごとにまとめて描き、`globalCompositeOperation` の切替を1フレーム2回に抑制
- 1粒ごとの `save()` / `restore()` を廃止し、`globalAlpha` と `setTransform` を直接操作
- 上限を1200→460個に。超過分は `slice`（新配列を作る）ではなく `splice` で古い順に破棄

**生成数**

| 場面 | 修正前 | 修正後 |
|---|---|---|
| ひとくちのバースト | 46 | 28 |
| ひとくちの噴射 | 10 | 7 |
| カウントダウンの噴射 | 10+i×6 | 8+i×4 |
| 発射の煙 | 44 | 22 |
| 発射の噴射 | 35ms間隔×16 | 55ms間隔×9 |
| 星のバースト | 12回×34 | 7回×22 |

**自動減量**

描画ループでフレーム時間を指数移動平均で監視し、26msを超えたら `fxScale` を
0.35まで段階的に下げ、19msを下回ったらゆっくり戻す。粒の生成数はすべて
`amount(n)` を通す。タブ復帰などの100ms超の飛びは計測に混ぜない。

### 効果（発射シーケンスを通しで実測）

| 指標 | 結果 |
|---|---|
| 粒のピーク | 290個（修正前は上限1200に張り付き） |
| 平均 | 0.28ms |
| 中央値 | 0.10ms |
| p95 | 1.40ms |
| 最大 | 4.10ms |
| 16.7ms超過フレーム | 877フレーム中 **0** |

描画結果も確認（絵文字バースト6196px・火花3259px、粒は寿命どおり0まで減る）。
実行時エラーなし。

### 再発防止

`CLAUDE.md` を新規作成し、原因・数値・ルール・計測手順を明文化した。

1. 毎フレームのループ内で `createRadialGradient` / `ctx.font` 代入 / `fillText` /
   `getBoundingClientRect` / オブジェクト生成をしない。起動時スプライト＋`drawImage`
2. 同時に生きる粒に必ず上限。破棄は `splice`
3. 種類ごとにまとめ描き。合成モード切替は1フレーム2回まで。粒ごとの `save/restore` 禁止
4. フレーム時間を監視して重い端末では自動減量
5. `setInterval` のエミッタは停止タイマーとリセット処理の両方から止める
6. CSS アニメーションは `transform` と `opacity` のみ
7. `prefers-reduced-motion` の分岐を必ず用意
8. 受け入れ基準: デスクトップ実測で p95 8ms 未満／最大 16.7ms 未満／予算超過0。
   見た目で判断せず必ず数字を出す（計測用スニペットを CLAUDE.md に収録）

診断用に `window.__mogu` へ `parts` / `fxScale` / `frameMs` を追加した。
